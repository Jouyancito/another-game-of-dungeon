## Los 3 gaps más importantes

### Gap 1 — Sin TARGET_SPEC medido para Filomeno

La referencia 2D (`filomeno_nude_apose.png`) NUNCA fue ingresada como `--target` en `compare_render.py`. Nunca se ejecutó la Phase 0 del VISUAL_READING_PROTOCOL con números reales (brow-gap como fracción del head-bbox, eye spacing, muzzle Y como % de la altura total). Sin ese spec, la oscilación ojos-lejos→cerca→lejos no tiene stop condition: Claude itera sin saber cuál es el número objetivo. Este es el modo de falla central de hoy.

**Fix mínimo:** `python compare_render.py -r face/orbit_v15/front.png -t corporeo-3d/_refs/filomeno_nude_apose.png -o ./tmp_compare --bg auto --align bbox` → leer la tabla de gaps generada → comprometer `TARGET_SPEC.md` con esos números.

### Gap 2 — compare_render.py no cubre la región cara (full-body pasa, cara falla)

El script compara imágenes completas. Un cuerpo 95% correcto con una cara 5% rota produce IoU alto, SSIM alto, y el script dice PASS. Los defectos que Joan detectó orbitando (boca bajo hocico, negro en cráneo, ojos raros) son defectos locales de una región pequeña. Sin un crop-and-compare de la región facial (bbox del hocico hacia arriba, ~30% de la altura total), el instrumento es ciego al problema.

**Fix mínimo:** agregar `--crop-region "x0,y0,x1,y1"` a `compare_render.py` (o un wrapper script `face_compare.py` que extrae el bbox de la cara antes de correr las métricas). Correr ese crop-compare en cada iteración antes del veredicto.

### Gap 3 — El loop de veredicto está desconectado de todos los instrumentos

La secuencia real de hoy fue: (1) Claude genera cambio en Blender, (2) Claude re-renderiza, (3) Claude lee imagen y emite veredicto. Los pasos (2.5a) correr `compare_render.py`, (2.5b) leer `metrics.json`, (2.5c) producir `FACE_compare.png` con números superpuestos nunca ocurrieron. No existe un "gate" que bloquee el veredicto si no hay JSON de métricas con la iteración. El VISUAL_READING_PROTOCOL dice exactamente eso en sus Hard Rules pero depende de auto-disciplina del constructor — que falla consistentemente (documentado 2026-06-19: agente auto-score 7/10 vs críticos independientes que vieron el desastre; repetido hoy con score real 1/5 post-órbita).

**Fix mínimo:** en el skill `blender-asset-smith`, convertir el paso "render → presenta resultado" en "render → `compare_render.py` → metrics.json → leer JSON → emitir gaps → THEN veredicto". El JSON es el unlock del veredicto. Sin él, Claude responde solo con los números del JSON (que no puede inventar).
